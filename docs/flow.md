# 流程（唯一流程来源）

本文件只用功能性用词：层、深度、根、节点、披露、互指连通分量、阈值。不用比喻。
（对照：此前称「互指连通分量」为「岛」，称单入口的根为「伞体」。本文件改用功能性名称。）
对话里的说法与它冲突，以它为准。

## 一、目标与输入输出

- **输入**：一整个 skill pack（含 1..N 个 skill 的目录树）。
- **做法**：构建文档树 → 在树上测出不符合阈值的文档 → 改动 → 重新构建并比较。
- **输出**：改过的 pack + 改动前后的两份文档树 + 对账结果。

## 二、阶段

| 阶段 | 名称 | 判断还是计算 | 产出 |
|---|---|---|---|
| A | 定形状（根的数量） | 判断（用户） | 形状 |
| B | 构建文档树 | 计算 | 文档树数据 + 文本表 + 图 |
| C | 在树上判断 | 判断（模型） | TODO.md |
| D | 改动文档树 | 判断出内容，计算落盘 | 可回滚的改动 + 提案记录 |
| E | 复测 | 计算 | 新文档树 + RUN.md + PARKED.md |
| F | 验收与交付 | 判断（判官模型）+ 计算 | 评测分数 + 合回真包 |

### A 定形状（根的数量）
- **对象**：文档树中根的数量。单入口 = 1 个根（该 pack 唯一入口的 `SKILL.md`）；多入口 = 每个 skill 的 `SKILL.md` 各为一个根。
- **谁判断**：用户。一句话即可。
- **产出**：形状。后面各阶段都按它执行。

### B 构建文档树
**这一步只做计算，不做判断**，四步：
1. **枚举文档**：扫描整个 pack，每份文件记为一个节点，并记录它所属的 skill（依据最近的 `SKILL.md` 所在目录）。
2. **解析披露**：读取每份文档正文中写出的路径，生成有向边。（URL、代码块内的路径、不带目录的裸文件名不计入。）指向 pack 之外的记为 `external`；指向不存在文件的记为悬空。
3. **计算层与深度**：从根开始沿披露边遍历：根为 L1，根直接披露的为 L2，L2 披露的为 L3，依次递推。遍历不到的文档记为「未被任何根披露」。
4. **计算体积与出度**：每份文档的字符数、估算 token、行数、披露了几份文档、被几份文档披露。
- **产出**：`disclosure.json`（节点、边、层、每节点度量）· `DISCLOSURE.md`（同数据的文本表）· 树图 · `tree.json` / `TREE.md`（同一棵树按目录层级的视图）。
- **说明**：体检不是独立阶段。树建好后，某份文档是否超过阈值，就是用它的类型对照阈值表（正文估算 token 与行数、`description` 字符数、资源文件字节数）；比对所需的量都已经在树里。

### C 在树上判断
- **对象**：分组、命名，以及需要改动哪些文档。判断项：
  1. **互指连通分量如何划分**（互指关系图只是证据，划分是判断）
  2. **层与类目的命名**
  3. **某份文档应由哪份文档披露**（未被任何根披露的文档：补一条披露、删除、或记为豁免）
  4. **唯一入口 `SKILL.md` 的 `description` 内容**（单入口形状下它决定整个 pack 能否被触发）
  5. **超过体积阈值的文档拆成几份、按什么主题拆**
- **谁判断**：模型。（用户在 A 阶段介入。）
- **产出**：`TODO.md` —— 每条 = 文档 · 问题类型 · 数值 · 建议动作 · 谁判。

### D 改动文档树
- **对象**：目录结构与文档内容。两类改动：
  1. **移动目录**：单入口形状下，把各 skill 目录移动到入口 skill 的 `references/` 下，并为每个互指连通分量增加一份 `INDEX.md`（列出该分量包含的 skill 及其触发条件）。
  2. **修改文档**：改正指向不存在文件的引用路径；把超过体积阈值的文档按主题拆成多份。
- **分工**：改动内容由模型决定；落盘由工具执行 —— 校验待改文本与文件当前内容一致、校验改动只落在允许的文件范围内、校验拆分前后内容守恒、移动用 `git mv` 保留内容未改的记录。
- **产出**：可回滚的改动（副本 + git 记录）+ 每条改动对应的提案记录。

### E 复测
- **对象**：改动前后两份文档树的差。四项判据：
  1. 目标问题消失（本次声明要解决的条目不再出现）
  2. 没有新增问题（按路径集合比较，不按数量比较）
  3. `external` 集合不变
  4. 拆分前后内容守恒（只搬移位置，不丢字）
- **谁判断**：无，全部是计算。任一项不通过则回滚整批，并改变下次执行时的输入（不是重复同一条指令）。
- **产出**：新的文档树 + `RUN.md`（每次执行的结果与被拦截的判据）+ `PARKED.md`（走到最后仍不通过的条目）。

### F 验收与交付
- **对象**：Agent 的选择结果。仅当改动涉及 `description`、入口 `SKILL.md` 或 `INDEX.md` 时执行：对一组固定题面做盲判，判据为「新结构得分 ≥ 旧结构得分，且没有题目从 1.0 掉到 0.5 以下」。
- **谁判断**：判官模型。
- **产出**：评测分数 + 把副本的改动合并回真包 + 报告与计划更新。

## 三、默认做法（可改，代价写在后面）

- **在副本上工作**：默认工作目录是 `prepare` 生成的副本，真包保持原样；副本内有 git 记录，可以回滚。直接改真包也可以，代价是没有回滚记录，出问题只能靠备份。
- **计算交工具，判断交模型**：B、E 是可计算的部分，交给工具；A、C、D 是判断，交给模型。工具可以给出草案（例如按标题草拟拆分方案），但草案要标明来源是工具，不作为结论使用。

## 四、实现映射（命令是各阶段的一种实现方式）

| 阶段 | 命令 | 产物 |
|---|---|---|
| A | `--shape single\|multi` | 形状 |
| B | `prepare`（生成副本 + 基线）→ `disclosure`（构建文档树 + 输出体检表）→ `tree` / `visualize`（其它视图） | `BASELINE.md` · `disclosure.json` · `DISCLOSURE.md` · `TREE.md` |
| C | `disclosure` 的输出 `TODO.md`；分组判断可用 `propose`（默认 dry-run） | `TODO.md` |
| D | `collapse`（单入口）/ `propose --apply-group`（多入口）；文档级改动 `apply`（未实现） | 改动 + 提案记录 |
| E | `verify` | 新文档树 + `RUN.md` / `PARKED.md` |
| F | `judge` + `score` → `git merge --ff-only` | 评测分数 + 合回 |

未实现的只有一处：D 阶段中文档级改动（修引用、拆超限文档）的落盘器 `apply`。A、B、C、E、F 都已有实现。
