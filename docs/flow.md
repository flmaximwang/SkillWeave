# 流程（按架构写；唯一流程来源）

流程只认这份文件。它讲**物体与产物**，不讲命令。命令在文末「实现映射」里，只是各阶段的一种实现方式。

## 一、这套东西在做什么

一句话：**把一整套 skill pack 变成一棵「文档树」，在树上量出问题，改树，再量一遍证明改对了。**

```
输入：一整个 pack（含 1..N 个 skill 的文件夹树）
  │
  ├─ A 取景     ：定形状 = 根有几个              ── 判断（用户一句话）
  ├─ B 建树     ：机械构建文档树                 ── 机械  ★
  ├─ C 读树     ：在树上做判断（切法/命名/待办） ── 判断
  ├─ D 改树     ：按待办改结构                   ── 判断出方案，机械落盘
  ├─ E 复测     ：重新建树 → 与基线对账          ── 机械
  └─ F 验收交付 ：证明效果没变差 → 合回真包       ── 判官 + 机械
输出：改过的 pack + 一棵新的文档树 + 对账证据
```

## 二、每个阶段（物体 · 谁判断 · 产物）

### A 取景 —— 定的是「根有几个」
- **物体**：树的根的数量。单入口 = 1 个根（伞的 `SKILL.md`）；多入口 = K 个根（每个 skill 的 `SKILL.md`）。
- **谁判断**：用户（一句话）。
- **产物**：形状 —— 后面所有阶段按它跑。

### B 机械构建文档树 ★ —— 就是这一步
**这一步不做任何判断，纯机械**，四个动作：
1. **认文档**：扫过一整个 pack，把每份文件认成节点（`SKILL.md` / `references/*.md` / `scripts/*.py` / `assets/*` …），并记下它属于哪个 skill。
2. **解析披露**：读每份文档正文里**真实点到**的路径（不算 URL、不算围栏里的示例、不算裸文件名），连成有向边；指出 pack 外的记 `external`，指到不存在的记悬空。
3. **算层与深度**：从根出发按披露走 —— `L1 = 根 → L2 = 根直接点到的 → L3 = L2 点到的 → …`；走不到的记「到不了根」。
4. **算体量与扇出**：每份文档的字符数 / 估算 token / 行数 / 披露了几项（fanout）/ 被几份文档点到（入度）。
- **产物**：**文档树本身** —— 机器版 `tree.json` / `disclosure.json`（节点 + 边 + 层 + 每节点的量）；人读版 `TREE.md` / `DISCLOSURE.md` / 树图。
- **关键**：体检**不是**另一个阶段 —— 树一建好，每份文档「是否超限」就是拿它自己的类型去过对应 cap（树里已经有它全部的量）。所以体检是 B 的出口，不单列。

### C 读树 —— 在树上做判断（没有机械可代劳）
- **物体**：树上的分组与命名。动作：**岛怎么切**（互指图只是证据，切法是判断）· **层/类目怎么命名** · **哪份文档该被谁披露** · **伞的那一条 description** · **某份超限文档拆成几份、按什么主题拆**。
- **谁判断**：模型（用户只在 A 介入）。
- **产物**：`TODO.md` —— 一条待办 = 一份文档 · 一个问题 · 数字 · 建议动作 · 谁判。这就是「问题清单」。

### D 改树 —— 按待办改结构
- **物体**：树的形状本身。两类改动：**搬家**（单入口时把 K 个根整棵搬进伞的 `references/`，加中间层 `INDEX.md`）与**修节点**（改错的引用路径、把超限文档按主题切成多份）。
- **谁判断**：改法由模型给（判断），落盘由工具做（机械：锚点校验、白名单、拆分守恒、`git mv` 留 rename 证据）。
- **产物**：一份可回滚的改动（副本 + git 历史）+ 逐条对应的提案记录。

### E 复测 —— 重新建树，与基线对账
- **物体**：同一棵树在两个时刻的差。判据：**该消的消了 · 无新增（集合级，不是比计数）· 外部引用集合不变 · 拆分守恒（只搬家不丢字）**。
- **谁判断**：无（纯机械）。失败 = 整批回滚 + 换输入重派（不是重复同一句话）。
- **产物**：新的一棵文档树 + `RUN.md`（过了没 / 哪条判据拦的）+ `PARKED.md`（卡住的）。

### F 验收交付 —— 证明「改完没变差」
- **物体**：Agent 的选择行为。只在动了 `description` / 伞体 / `INDEX.md` 时跑：拿一批**冻结的题面**做盲判，判据「新 ≥ 旧 且无题从 1.0 掉到 <0.5」。
- **谁判断**：判官模型。
- **产物**：评测分 + 合回真包（真跑即 production，不需额外批准）+ 报告与计划落账。

## 三、两条硬规矩

- **真包只读，工作区是副本**：改动只在副本上做（副本内 git 化 → 可回滚）；真包只在 F 阶段被合回。测试只在副本上；真跑 SkillWeave 本身就是 production，无需批准。
- **机械的归工具，判断的归模型**：B、E 全机械；A、C、D 的判断不许工具代笔（伞的 description、拆几份、该删还是该留）。

## 四、实现映射（命令只是 B..F 的一种实现方式）

| 阶段 | 命令 | 产物 |
|---|---|---|
| A | `--shape single\|multi` | 形状 |
| B | `prepare`（出副本 + 基线）→ `disclosure`（建树 + 体检出口）→ `tree` / `visualize`（视图） | `BASELINE.md` · `disclosure.json` · `DISCLOSURE.md` · `TREE.md` |
| C | `disclosure` 的出口 `TODO.md`；分组用 `propose`（dry-run） | `TODO.md` |
| D | `collapse`（单入口）/ `propose --apply-group`（多入口）；节点级改动 `apply`（**未建**） | 改动 + 提案记录 |
| E | `verify` | 新树 + `RUN.md` / `PARKED.md` |
| F | `judge` + `score` → `git merge --ff-only` | 评测分 + 合回 |

**没建的只有一处**：D 阶段里「按提案改节点」（修引用 / 拆超限文档）的落盘器 `apply`。A、B、C、E、F 都已有实现。
