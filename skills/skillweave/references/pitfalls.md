# 坑与经验（真跑撞出来的，都已在工具里修掉，写在这里免得重踩）

格式：**问题 → 根因 → 解决方案 → 如何避免**。

## 1. 删行别按内容锚点找

- **问题**：改文档时按「内容」定位要删的行，实测把正文删串了。
- **根因**：空行到处一样，按内容找会命中错误位置。
- **解决方案**：删行要按**行号 + 内容双严格**，且同文件内按行号**降序**应用。
- **如何避免**：`apply` 的校验就是「锚点在该行 ±3 内逐字相同」—— 永远带行号，别只带内容。

## 2. 拆段落 = 一行指针 + 删掉整段

- **问题**：拆分时容易把内容拆丢或拆重。
- **根因**：拆分的语义有两种，混在一起就判不清。
- **解决方案**：`after: null` 删行；指针写一行（`## 坑 → 见 \`references/x.md\``）。整篇拆分才用
  `parts` + 守恒校验；**`parts` 拼起来等于原文就按拆分处理（删原件），不等于才当搬出（留原件）**。
- **如何避免**：把「拆分守恒」当硬闸 —— 目的是区分「搬走了」和「删掉了」。

## 3. 搬完还要再看一眼

- **问题**：搬出去的 174 行清单自己就超了上限，得再拆一次。
- **根因**：只盯着源文件，忘了新文件也是一份文档、也要过它那类 cap。
- **解决方案**：拆完别忘让新文件**被披露**（指针行就是那条披露）；新文件自身超限就再拆。
- **如何避免**：`disclosure` 对**每一份文档**跑它那类 cap，改完重跑就能看到新文件的判定。

## 4. 回退顺序

- **问题**：一条改动涉及「新建文件 + 拆掉原件 + 改行」时，回退顺序错了会留下半成品。
- **根因**：三类改动有依赖方向。
- **解决方案**：先删新文件 → 再恢复被拆掉的原件 → 最后回退行改动；被拆掉的原件不再回退行。
- **如何避免**：每个条目落盘都写进 `dispatch/patches.json`，回退粒度是单条
  （`apply --revert <条目 id>`）。

## 5. 口径改了要重建基线

- **问题**：工具修了路径解析之后，`verify` 报「external 集合变了」。
- **根因**：旧基线里的 `external` 集合是**按旧口径**算的，口径一变，集合整体变。
- **解决方案**：这是正常的 —— 用 `dispatch --refresh-baseline` 重建基线再验。
- **如何避免**：基线冻在 pack 里（`dispatch/baseline.json`），口径变更时显式刷新，别把正常变化
  当成回归。

## 6. 塌完必须 commit 再跑 `visualize`

- **问题**：`collapse --apply` 后跑 `visualize` 静默出一棵空树（退出码 0）。
- **根因**：`collapse` 只改工作区，索引里还是旧路径；新入口的 `SKILL.md` 被当未跟踪跳过。
- **解决方案**：先 `git add -A` / commit 再跑 `visualize`。
- **如何避免**：`visualize` 现在有护栏 —— 工作区里存在**未被 git 跟踪**的 `SKILL.md` 时报错退出（退 1）
  并提示先 commit。

## 7. 「工具自己读得通」不等于文件合法

- **问题**：写出的 `SKILL.md` frontmatter 在真解析器里报 `mapping values are not allowed here`。
- **根因**：工具自带的 `parse_frontmatter()` 是手写的宽松子集，吃得下 `description: a: b` 这种坏写法。
- **解决方案**：写 frontmatter 的值一律经 `yaml_scalar()`（带 `: `、` #`、`>-` 的加双引号转义）；
  判合法性看 `frontmatter_selfcheck()` 或真 YAML 解析器。
- **如何避免**：`collapse --apply` 落盘后回读校验「顶层技能数 == 1 · 入口层 == 1 · frontmatter 自检
  通过 · description 逐字一致」，任一条不过就非 0 退出。

## 8. 岛数对口径敏感，报数必须连口径一起报

- **问题**：同一份数据能报出 11 / 10 / 13 个岛。
- **根因**：互指边的口径不同（只看 frontmatter `name` / 再加「引用落到别的 skill 目录」/ 扫全部文本
  文件按目录名）。
- **解决方案**：选**目录名**口径（包内既有的稳定标识，`name` 与目录名不总一致）。
- **如何避免**：报岛数时连口径一起写出来。

## 9. 单入口下 `孤儿`/`悬空` 会归零是构造性假象

- **问题**：塌成单入口后 `孤儿`/`悬空` 归零，看起来像问题被修好了。
- **根因**：伞体按**目录**点名了每个 `references/<岛>/`，目录级点名把里面全盖住了。
- **解决方案**：知道这是指标失去分辨力，不是真的干净。
- **如何避免**：单入口形状下这两项不当作「变好了」的证据；换用别的判据（分数、路由）。

## 10. 一致口径：`.skillweave/` 三处都要跳过

- **问题**：同一个包跑两遍给出两个数。
- **根因**：工具自己写下的产物（`DISCLOSURE.md` 等）被下一次运行量成一份「到不了根」的文档 ——
  `_pack_files()` 一开始排除了 `.skillweave/`，`walk_dir` 没排除，两处口径不一致。
- **解决方案**：`walk_dir`（文档树）、`analyze_skill`（skill 文件清单）、`graph._pack_files()` 三处
  一律跳过。
- **如何避免**：新增会走树的代码路径时，先确认它用了同一份 `SKIP_DIRS`。
