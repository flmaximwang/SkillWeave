# 并（merge）：同层近重复技能的处理

**目标**：同一层里两个技能在抢同一批提问时，Agent 只能掷硬币。要么合并，要么把界限写清楚（二选一，不能不理）。

## 判据（谁和谁在抢）

```bash
python3 "$SW" audit "$PACK" --out /tmp/sw
```

看 `dup` 段：同层（同一父目录）两两比 `description` 与摘要得出的相似度，`pairs_top` 是候选，
`pairs_over_050` 是超过 0.5 的对数。**分数高不等于必须合并** —— 先取证再决定。

## 取证（合并前必须有证据）

对每一对候选，逐条查：

1. **`description` 是不是逐字相同**（`.95` 以上基本就是复制来的）；
2. **正文的主体流程是否同一件**（读两边的「什么时候用」+ 目录结构，不看名字）；
3. **文件是否重复**（`tree.json` 里两边的 `files[].sha256` 交集）；
4. **是否各有独家内容**（只有一边有的 `references/`、脚本、分支）；
5. **谁在被引用**（`grep -rl "<另一个的名字>" <pack>` —— 别把被大量转指的那个删了）。

## 决定（两条路，都要写明理由）

- **真重复** → 合并：以「内容更全、被引用更多」的那个为主，把对方的独家段落折进主技能的对应小节，
  然后删掉被折的那份。
- **不是重复（只是名字像 / 场景接近）** → **写清界限**：在两个 `description` 里各加一句
  「**不属于**：<那种请求> → 用 <另一个技能名>」，并让触发词互斥（这是 `references/rewrite.md` 的活）。

## 落盘 + 验收

```bash
cp -R "$PACK" /tmp/pack-fix && cd /tmp/pack-fix
# 合并：折内容 → 删被折目录 → 修引用
git rm -r skills/<被折技能>            # (git 跟踪时)
python3 "$SW" tree   /tmp/pack-fix --out /tmp/sw-fix    # broken/orphans 不许新增
python3 "$SW" audit  /tmp/pack-fix --out /tmp/sw-fix    # dup 段：这一对必须从 top 里消失
python3 "$SW" layers /tmp/pack-fix --out /tmp/sw-fix    # L1 条目数随之下降
```

**路由不退化要靠评测**：合并会改变「哪些候选同时出现」，必须跑一轮路由评测（T-005 的口径：
候选只给 `description`、判官只看那一份文件、按层 fanout 报校正随机分）才能说「变好了」。
没跑评测的合并只算「结构变干净」，不算「路由变好」。

## 反例

- 因为相似度高就把两个**不同软件轴**的技能合并（提问的人分得清，你合并后反而没人认领）。
- 合并时只留一边的正文、把另一边的判据/错误串丢掉（丢的是实测来的知识）。
- 删掉一个还被别的技能转指的技能（先把转指改对，再删）。
