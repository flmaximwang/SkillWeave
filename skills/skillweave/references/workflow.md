# 流程：A → B → C → D → E → F 六阶段

唯一流程来源（长文版见仓库 `docs/flow.md`，按架构写）。本文件只用功能性用词：层、深度、根、节点、
披露、互指连通分量、阈值、批次；不用比喻。

**目标与输入输出**：

- 输入：一整个 skill pack，即含 1..N 个 skill 的目录树。
- 做法：构建文档树 → 测出不符合阈值的文档 → 改动 → 再构建一次并比较。**改动是多批次的循环，不是一次跑完。**
- 输出：改过的 pack + 改动前后的两份文档树 + 对账结果 + 未解决条目的清单。

## 循环结构

```
A 定形状：定根的数量，只做一次

循环开始 ────────────────────────────────────────────┐
  B 构建文档树       每次进循环都重做，产出当前树         │
  C 在树上判断       从当前树产出待办清单 TODO.md        │
  D 改动文档树       取一批待办，改这一批                │
  E 复测             与上一轮迭代结束时的树比较          │
      通过            保留本批改动，还有待办 → 回 B       │
      部分通过        保留通过的条目，只对未通过的条目    │
                      改变输入后回 D 继续修              │
      无法修正        回退这一条改动，其它条目保留        │
      无法解决        写入 PARKED.md，继续下一批          │
循环结束 ────────────────────────────────────────────┘
  条件：待办清单里除已记为豁免与 PARKED 的条目外，没有剩余

F 验收与交付：跑盲判，通过则合回真包
      得分退化或题面掉分 → 回 C 重新判断
```

## 各阶段

| 阶段 | 名称 | 判断还是计算 | 产出 | 命令 |
|---|---|---|---|---|
| A | 定形状：根的数量 | 判断，用户 | 形状 | `--shape single\|multi` |
| B | 构建文档树 | 计算 | 树数据 + 文本表 + 图 | `prepare` · `disclosure` · `tree` · `visualize` |
| C | 在树上判断 | 判断，模型 | `TODO.md` | `disclosure` 的 `TODO.md` · `propose` |
| D | 改动文档树 | 判断出内容，计算落盘 | 可回滚的一批改动 + 提案记录 | `collapse` · `propose --apply-group` · `apply` |
| E | 复测 | 计算 | 新树 + `RUN.md` + `PARKED.md` | `verify` |
| F | 验收与交付 | 判断，判官模型，加计算 | 评测分数 + 合回真包 | `judge` · `score` · `deliver` |

### A 定形状：根的数量

- 对象：文档树中根的数量。单入口即 1 个根（该 pack 唯一入口的 `SKILL.md`）；多入口即每个 skill 的
  `SKILL.md` 各为一个根。
- 谁判断：用户，一句话即可。
- 产出：形状。循环内各阶段都按它执行。

### B 构建文档树

只做计算，不做判断，四步：

1. **枚举文档**：扫描整个 pack，每份文件记为一个节点，并记录它所属的 skill（依据 = 最近的
   `SKILL.md` 所在目录）。
2. **解析披露**：读取每份文档正文中写出的路径，生成有向边。URL、代码块内的路径、不带目录的裸文件名
   不计入。指向 pack 之外的记 `external`；指向不存在文件的记悬空。
3. **计算层与深度**：从根开始沿披露边遍历。根为 L1，根直接披露的为 L2，依次递推。遍历不到的文档
   记为「未被任何根披露」。
4. **计算体积与出度**：每份文档的字符数、估算 token、行数、披露了几份文档、被几份文档披露。

- 产出：`disclosure.json`（节点、边、层、每节点度量）· `DISCLOSURE.md`（同数据的文本表）· 树图 ·
  `tree.json` 与 `TREE.md`（同一棵树按目录层级的视图）。
- 说明：**体检不是独立阶段**。树建好后，某份文档是否超过阈值，就是用它那类 cap 比对 —— 比对所需的
  量都已在树里。

### C 在树上判断

- 对象：分组、命名，以及需要改动哪些文档。判断项：
  1. 互指连通分量如何划分（互指关系图只是证据，划分是判断）。
  2. 层与类目的命名。
  3. 某份文档应由哪份文档披露（未被任何根披露的文档：补一条披露、删除、或记为豁免）。
  4. 唯一入口 `SKILL.md` 的 `description` 内容（单入口形状下它决定整个 pack 能否被触发）。
  5. 超过体积阈值的文档拆成几份、按什么主题拆。
- 谁判断：模型。用户在 A 阶段介入。
- 产出：`TODO.md`，每条含文档、问题类型、数值、建议动作、谁判。

### D 改动文档树

- 对象：目录结构与文档内容。两类改动：
  1. **移动目录**：单入口形状下，把各 skill 目录移动到入口 skill 的 `references/` 下，并为每个互指
     连通分量增加一份 `INDEX.md`，列出该分量包含的 skill 及其触发条件。
  2. **修改文档**：改正指向不存在文件的引用路径；把超过体积阈值的文档按主题拆成多份。
- 分工：改动内容由模型决定；落盘由工具执行，校验四件事 —— 待改文本与文件当前内容一致、改动只落在
  允许的文件范围内、拆分前后内容守恒、移动用 `git mv` 保留内容未改的记录。
- **逐条记录 patch**：每落一条改动就记下它改了哪些文件、哪些行、旧内容与新内容。有了这份记录，回退
  可以只回退一条；没有它，回退粒度只能是整批。
- 一次只取一批待办执行，批次内部的条目互不相交，避免两个执行者改同一份文件。
- 产出：可回滚的一批改动（副本 git 记录 + 逐条 patch 记录 + 每条改动对应的提案记录）。

### E 复测

- 对象：本批改动前后两份文档树的差。四项判据：
  1. 目标问题消失（本批声明要解决的条目不再出现）。
  2. 没有新增问题（按路径集合比较，不按数量比较）。
  3. `external` 集合不变。
  4. 拆分前后内容守恒（只搬移位置，不丢字）。
- 谁判断：无，全部是计算。判据对照上一轮迭代结束时的树，所以本轮只对本轮改动负责。
- 不通过时：**不回滚整批**。通过的条目保留；未通过的条目改变输入后回 D 继续修；只有无法修正的条目
  才回退它自己那一条 patch。
- 产出：新的文档树 + `RUN.md`（每次执行的结果与被拦截的判据）+ `PARKED.md`（走到上限仍不通过的条目）。

### F 验收与交付

- 对象：Agent 的选择结果。**仅当**改动涉及 `description`、入口 `SKILL.md` 或 `INDEX.md` 时执行：
  对一组固定题面做盲判，判据为新结构得分不低于旧结构，且没有题目从 1.0 掉到 0.5 以下。
- 谁判断：判官模型。
- 产出：评测分数 + 把副本的改动合并回真包 + 报告与计划更新。
- **合回真包 main 是默认动作，不是等人点头的动作**：`deliver <工作副本>` 一次做完 —— 合回真包 `main`
  （只走 `--ff-only`）→ push 各 remote 并**回读** → 重跑 `visualize` → 删 worktree、删分支。
  把改动留在副本里、让真包继续显示旧形状，才是需要理由的那一侧（写法：`--keep-worktree` / `--no-push`）。

## 循环的控制参数

- **单批重试上限**：同一个条目最多执行 4 次。第 1 次直接执行；第 2 次带上上次的失败证据，在已改动的
  树上继续修；第 3 次缩小范围到单个条目，并把可查到的事实直接给出；第 4 次换执行者。4 次仍不通过则
  记入 `PARKED.md`，必要时回退这一条 patch，继续处理其它条目。
- **回退粒度**：单条 patch，不整批（前提是 D 阶段逐条记录了 patch）。
- **输入必须变化**：同一个条目重试时，执行指令的哈希值不得与上次相同；相同则拒绝执行。
- **全局守卫**：每轮迭代后，相对会话起点的待办集合只允许缩小或不变。**对比基线随迭代前移** ——
  每轮的判据只针对本轮改动。
- **计数位置**：次数记录在 `state.json`，不依赖任何执行者的记忆。
- **每批结束都重建文档树**，因为改动会改变层与深度。
- 待办清单里已记为豁免的条目不进入循环（豁免规则写在 pack 内的 `.skillweave/waivers.txt`）。

## 终止条件

待办清单中只剩已豁免与已记入 `PARKED.md` 的条目，**且**验收（F）通过。

## 三层回退

1. **E → D：同一批的继续修正。** 复测不通过时**不整批回滚**：通过的条目保留，只对未通过的条目改变
   输入后回 D 继续修；输入没变就不重派，避免原地重复。只有某条改动本身无法在不撤销的情况下修正时，
   才**回退这一条**，其它条目保留。
2. **E → B：下一批。** 通过则重新构建文档树，因为树变了，判断必须基于新的树。
3. **F → C 或 F → A：验收回退。** 得分退化则回到判断阶段重新决定改什么；若连形状都不再满足要求
   （例如入口数量需要变化），则回到 A。

## 默认做法（可改，代价写在后面）

- **在副本上工作**：默认工作目录是 `prepare` 生成的副本，真包保持原样到你走完流程，副本内有 git 记录
  可以回滚。**副本不是终点**：流程走完（E 通过、F 该跑就跑）默认由 `deliver` 合回真包 `main` + push
  各 remote + 清 worktree/分支。直接在真包上改也可以，代价是没有回滚记录。
- **计算交工具，判断交模型**：B 与 E 是可计算的部分，交给工具；A / C / D 是判断，交给模型。工具可以
  给出草案（例如按标题草拟拆分方案），但草案要标明来源是工具，不作为结论使用。
