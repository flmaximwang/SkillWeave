# 核心概念：文档树 · 层 · 披露 · 形状 · caps

本文件是 SkillWeave 的口径来源（长文版见仓库 `docs/contract.md`）。所有脚本、报告、判据都按它读。

**输入的单位是 pack，不是单个 skill**：一个 skill pack = 一个仓库/目录，含 1..N 个 skill；
输入 = 一整套含 `SKILL.md` 的文件夹树（工具自己认出 skill / 类目 / 资源）。

契约是 [agentskills.io 规范](https://agentskills.io/specification)：`<skill 名>/SKILL.md` + 可选
`scripts/` `references/` `assets/`。工具**不依赖任何 agent 框架**：输入只有目录与文件，
不认识任何 agent 侧的目录约定、安装器或状态文件。

---

## 1. 节点 = 一份文档

- **节点 = 一份文档**（`SKILL.md`、`references/*.md`、`scripts/*.py`… 各算一份），每份记它所属的 skill。
- **每份文档的量**：字符数、估算 token、行数、披露了几项（fanout）、被几项披露。
- **估算 token 口径**：CJK 字符 ×1 + 其它字符 ×0.25，四舍五入（**估算**，报告里必须写明）。
- pack 在 git 仓库里时只算 **git 跟踪**文件；目录里的未跟踪垃圾会被单列、不混进任何度量。
  刚新建还没提交的技能目录也会被算作未跟踪 —— 先提交再量。

## 2. 层 = 披露深度

**层不是文件类型，也不是「选择发生的级」——层是文档之间的披露关系：**

- **L1 = 根文档**（`SKILL.md`）——Agent 最先拿到的那份。
- **L2 = L1 直接披露的文档**（L1 正文里真实点到的路径）。
- **L3 = L2 直接披露的** …… **Lₙ₊₁ 由 Lₙ 披露**。

「一层摆出几项」= **该层每份文档各自披露了几项**（fanout），不是「全 pack 的描述菜单有多大」。

## 3. 披露 = 正文里真实点到的另一份文档

- **一条披露** = 一份文档正文里真的写出了另一份文档的路径。
- **不算披露**：URL、代码围栏里的示例路径、没有目录部分的裸文件名（`run.py`、`fig.pdf` 这类；
  裸 `SKILL.md` 是自指，仍按 resolved 记）。
- **解析基准**（依次尝试）：该文件所在目录 → 该 skill 目录 → **最近的 `SKILL.md` 所在目录**
  （嵌套 skill 的相对引用按它自己的根写）→ pack 根。
- **path 字符集含非 ASCII**：包里的文件名可能是中文，只认 ASCII 会把它们误判成「到不了根」。
- 指出 pack 外的记 `external`（不算披露、也不算错）；指到不存在文件的记**悬空**。
- **目录级点名**：正文**整段**点名一个目录路径（如 `` `scripts/weavelib/` ``）时，该目录下的文档都算被它
  披露到（目录不存在不计悬空）。
- **脚本类文档不做「悬空」检查**：`scripts/**` 或脚本后缀的文件里，路径字面量多是 fixture 与注释里的举例，
  不是披露意图（与「脚本不设字节上限」同源）；脚本的唯一披露要求是被所属 `SKILL.md` 点名。markdown 里的悬空照报。

## 4. 形状 = 根的数量

**根 = 每个 skill 的 `SKILL.md`**；根有几个就是形状。

| 形状 | 根 | 典型 | 代价 |
|---|---|---|---|
| **多入口**（默认） | **K 个根**（每个 skill 的 `SKILL.md` 都是可能的 L1，Agent 先按 description 选根） | 39 个 skill → 39 个根 | 常驻 = 全部 description；独立可装 = K |
| **单入口**（`collapse`，可选） | **1 个根**（伞的 `SKILL.md`，其余全是它的 `references/`） | 伞 → 13 岛 → 39 篇正文 → 118 份资源 | 常驻 = 1 条 description；**独立可装 = 1** |

形状是**启动参数**（`--shape single|multi`），在准备之前就定 —— 不让用户等到中途拍板。

UsingHermes 实测（`weave.py disclosure`，2026-10-11）：

```
单入口：L1=1 → L2=13 → L3=39 → L4=118 · 到不了根=31 · 文档 202 份 · 超限 10 · 悬空 130 · external 389
多入口：L1=39 → L2=118 → L3=3          · 到不了根=28 · 文档 188 份 · 超限 10 · 悬空  91 · external 388
```

## 5. caps（阈值）与出处

只认两类来源：**agentskills.io 规范**（硬约束，违规记「错误」）与 **Anthropic Skills 最佳实践**
（建议值，违规记「警告」，只提示不拦）。表与 `weavelib/common.py` 的 `CAPS` 同源。

| 检查项 | 上限 | 来源 | 违规时行为 |
|---|---|---|---|
| `name` | ≤ **64** 字符 | agentskills.io 规范 | 错误 |
| `description` | ≤ **1024** 字符 | agentskills.io 规范（硬约束） | 错误 |
| `SKILL.md` 正文 | 建议 < **5000** token | Anthropic Skills 最佳实践 | 警告 |
| `SKILL.md` 行数 | 建议 < **500** 行 | Anthropic Skills 最佳实践 | 警告 |
| `references/` 单文件 | 建议 < **300** 行 | Anthropic Skills 最佳实践 | 警告 |
| `scripts/**` 或脚本后缀文件 | **不设字节上限**（不进超限清单、不建议拆） | 包主口径 2026-10-12 | — |

- **已删除的旧口径**：Dream 的 20000 B 资源上限、50/150/500 行三档、`MAX_FIRST_LAYER=20` 硬闸。
  入口层条目数只留一条**工程参考线**（`FIRST_LAYER_REFERENCE = 20`），超了只提示、不拦命令。
- **脚本为什么不设上限**：Agent 从不整份读脚本 —— 它读 `SKILL.md` 里的调用说明 + 按需 grep。
  脚本这边唯一的披露要求：**被所属的 `SKILL.md` 点名**（不点名就是孤儿）。
- **fanout 不设死值**，报分布 + 校正随机分；每个数字都必须能追到
  `docs/similar-work.md` / `docs/prior-art.md`，**不许出现没有出处的自创数字**。

## 6. 跨文档发现

- **到不了根（旧名「孤儿」）**：从任何根顺着披露都走不到它（in-degree 0 且非根）。0 容忍，
  但报告里只列清单、不自动删；点名含**目录级**（点名 `scripts/weavelib/` ⇒ 整目录都算被点名）。
- **悬空**：写了像本 pack 内的路径，但那个文件不存在。报告里**按文件聚合成一行**。
  **脚本类文档不做这条检查**（脚本里的路径字面量不是披露意图）；markdown 里的悬空照报。
- **近重复（抢题）**：同层两份文档太像，Agent 会选错。`audit` 的 dup 段与 `propose` 的
  merge/rewrite 候选共用 `dup_pairs(pack)`，算**两个分组口径**：`parent`（同一父目录的兄弟）与
  `entry`（单入口形状下的岛×岛）。候选 = 字面分 ≥ 0.5 **或**命中一个非字面信号
  （`related_skills` / 同款文件名 / name 词元，各带 `df ≤ 2` 闸）。

## 7. 术语表（报告里出现这些词就是这些意思）

| 词 | 定义 |
|---|---|
| 文档 / 节点 | 一份文件（`SKILL.md`、`references/*.md`、`scripts/*.py` 各算一份） |
| 根 | 起点文档 = 一个 skill 的 `SKILL.md`；**根有几个 = 形状**（1 = 单入口，K = 多入口） |
| 披露 | 一份文档正文里真的写出了另一份的路径；**不算**：URL、围栏里的示例路径、没有目录的裸文件名 |
| L1 / L2 / … | 离根几步（根 = L1） |
| fanout | 该文档披露了几份别的文档 |
| 到不了根 | 从任何根顺着披露都走不到它（in-degree 0 且非根）；旧名「孤儿」 |
| 超限 | 超过它那类的上限；**报告必须写超多少** |
| 悬空 | 写了像本 pack 内的路径但文件不存在 |
| external | 正文里提到的本 pack 之外的文件（不算披露、也不算错） |
| 近重复 | 同层两份文档太像（描述或内容），Agent 会选错 |

**报数规则**：报告里出现上面任何一个词，读者都应能只靠这张表读懂；数字必须能被同一条命令复跑出来。

## 8. 免检表与自动豁免

- **出口是 `TODO.md`**（不是体检表）：每条 = `文档 · 问题 · 数字 · 建议动作 · 谁判`；
  谁判只有 `机械可判` 与 `待模型` 两种。
- **免检表在包里、不在工具里**：`<pack>/.skillweave/waivers.txt`，一行一条 `<glob>` + 两个以上空格 +
  理由（`#` 注释）。命中的进「已豁免」栏并单独计数 —— 「哪张 png 是给人看的」「哪个 json 是测试留档」
  是**包主的判断**，不是通用真理。
- **资源目录自动豁免**：`templates/` · `examples/` · `tests/` 三个目录下的文件**不要求**被 `SKILL.md`
  显式引用，自动记入「已豁免」，**无需**写进 `waivers.txt`。若这些文件确实被引用，仍照常验证路径正确性
  （悬空照报）—— 豁免的只是「到不了根」这一条。
- **`.skillweave/` 是非成员目录**（与 `.git` / `__pycache__` 同级）：走树时一律跳过，工具自己写下的
  产物不会被下一次运行量成「到不了根」。
