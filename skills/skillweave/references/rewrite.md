# 改写（rewrite）：改 `description` 的触发词

**目标**：`description` 是 **L1 唯一的信号**（Agent 只看到这一行就决定要不要进来）。改写是**行为修改**，
不是文案修改 —— 改完必须能证明「该触发的触发、不该触发的没被抢走」。

## 判据（先看现状）

```bash
python3 "$SW" layers "$PACK" --out /tmp/sw      # L1：description 长度分布、常驻 token
python3 "$SW" audit  "$PACK" --out /tmp/sw      # dup：同层相似度（改写要拉开它）
```

- 规范硬约束：`description` ≤ **1024 字符**；建议前 **57 字符**自足（那是被截断显示的那一段）。
- 长度不是重点，**触发词是否是提问者会说的那个词**才是。

## 改写规则（按顺序）

1. **前 57 字符写「做什么 + 什么时候用」**，且用**提问者会脱口而出的词**，不是你自己给这个话题起的名字。
2. **触发词排在排除条款之前**；排除条款（「**不属于**：… → 用 X」）放尾部，别挤掉前面的信号。
3. **一个钩子进来，就得有一个旧钩子让位**：57 字符窗口是硬限制，塞新词会挤掉旧词 ——
   被挤掉的那个词对应的提问会**静默转投**最像的兄弟技能。改前先记下现有触发词清单。
4. **同层互斥**：与相似度高的兄弟（`audit` 的 `dup` 段）对读一遍，确保两边各自认领的提问不重叠；
   重叠的用「不属于」条款切开。
5. **别改名当改写**：改目录名不改窗口，触发词一个字没动 —— 那不算改写（改名只影响路径）。

## 重测（唯一验收）

改写无法靠肉眼验收，必须跑一轮路由评测：

- 候选表 = **各技能 `description` 的前 57 字符**（截断口径要写清）；
- 判官 = ≥2 个**独立**会话，只读那一份候选+题面文件，逐题选一个技能或 `none`；
- 金标 = 每题一个归属技能 + 题型（该触发 / 不该触发）；
- 报分**分组**：原有触发词组 / 新增能力组 / 兄弟干扰项组；总分接近时只有「新增能力组」有意义；
- **校正随机**：同一层的选项数不同，裸成功率不可直接比，报「比随机好多少」。

改动同时要把「接受的代价」写下来（哪道题稳定漏给哪个兄弟、为什么是取舍不是缺陷）。

## 反例

- 只加形容词（「更强的」「专业的」）—— 那些不是触发词，白占窗口。
- 为了覆盖更多场景把三个技能的触发词都写成同一批词（结果是三个都变糊）。
- 改完不重测，凭感觉说「更清楚了」。
